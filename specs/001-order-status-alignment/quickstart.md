# Quickstart: ตรวจว่าสถานะ Order ตรงตามที่ทีมอนุมัติ

ใช้เดินด้วยมือหลังทำ tasks เสร็จ (constitution ไม่บังคับให้มี automated test)
รายละเอียดข้อมูลตั้งต้นอยู่ใน [data-model.md](./data-model.md) พฤติกรรมที่ต้องได้อยู่ใน [contracts/order-status-flow.md](./contracts/order-status-flow.md)

## เตรียมการ

```bash
npm install
npm run lint
npx tsc --noEmit
npm run build
npm run dev          # http://localhost:3000
```

เข้าสู่ระบบด้วย `admin@colorado.jp` / `demo1234` แล้วเปิด `/dev` กด "รีเซ็ตข้อมูลตัวอย่าง" ก่อนเริ่มทุกสถานการณ์ (ปิด fault ทั้งหมด)
ถ้าใช้เบราว์เซอร์เดิมที่เคยเปิดระบบ ให้ตรวจว่าหน้าโหลดข้อมูลชุดใหม่ (มี `ORD-24165` และ `ORD-24166`)

## สถานการณ์

| # | ทำอะไร | ต้องเห็น | ครอบคลุม |
|---|---|---|---|
| 1 | หน้า `/shipping` เปิดครั้งแรกหลังรีเซ็ต | `ORD-24166` เป็น "จัดส่งสำเร็จ" (ขนส่งตอบส่งถึง); `ORD-24165` ยังเป็น "อยู่ระหว่างจัดส่ง" แต่สถานะขนส่งเป็น "ส่งถึงลูกค้าแล้ว"; `ORD-24174` สถานะขนส่งอยู่ระหว่างทาง | US2, FR-004, FR-005 |
| 2 | กด "ส่งเลขติดตามให้ลูกค้า" ที่ `ORD-24174` | toast ส่งสำเร็จ และ toast ตัดสต๊อกสำเร็จ; Order เป็น "แจ้งเลขติดตามแล้ว" มีข้อความ "ตัดสต๊อกแล้ว" และ**ไม่**เป็น "จัดส่งสำเร็จ"; สต๊อกของ SKU ลดลงเท่าจำนวนสั่งหนึ่งครั้ง (ดูที่ `/products/stock`) | US1, FR-001, SC-002 |
| 3 | ออกจากหน้าแล้วกลับมา / ดึงซ้ำ | `ORD-24174` ยังเป็น "แจ้งเลขติดตามแล้ว" สต๊อกไม่ลดซ้ำ | FR-002 |
| 4 | กด "ส่งเลขติดตามให้ลูกค้า" ที่ `ORD-24165` | ตัดสต๊อกแล้วเลื่อนเป็น "จัดส่งสำเร็จ" ทันที (ขนส่งยืนยันไว้ก่อนแล้ว) | FR-005 |
| 5 | กดส่งเลขติดตามซ้ำที่ Order "แจ้งเลขติดตามแล้ว" (เช่น `ORD-24174`) | ปุ่มยังแสดง; มี dialog ยืนยันส่งซ้ำ; ส่งแล้วสถานะไม่เปลี่ยน | US3, FR-011 |
| 6 | เปิดหน้า `/shipping` ที่ `ORD-24173` และ `ORD-24172` | `ORD-24173` เป็น "จัดส่งไม่สำเร็จ"; `ORD-24172` เป็น "ตีกลับ/คืนสินค้า" และสต๊อกถูกคืนตามจำนวน | FR-006, SC-004 |
| 7 | `/orders/cancel` ยกเลิก Order "แจ้งเลขติดตามแล้ว" (เช่น `ORD-24174` ถ้ายังไม่ถึงข้อ 4) | แจ้งว่ายกเลิกในระบบทันทีไม่ได้ และเป็น "รอดำเนินการพิเศษ" ไม่คืนสต๊อก | US3, FR-009 |
| 8 | `/orders/cancel` ลองยกเลิก Order "จัดส่งสำเร็จ" | แจ้งว่ายกเลิกไม่ได้ | FR-009, SC-005 |
| 9 | `/system/cleanup` เลือกลบ Order ที่ปิดแล้ว | รายการมีเฉพาะ "จัดส่งสำเร็จ" และ "ยกเลิกแล้ว"; ไม่มี Order ที่ยัง "แจ้งเลขติดตามแล้ว" | FR-010, SC-005 |
| 10 | เปิด fault "mpStockSync" ใน `/dev` แล้วเดินสถานการณ์ 2 กับ Order ใหม่; แล้วเดินสถานการณ์ 4 กับ `ORD-24165` ขณะ fault ยังเปิดอยู่ | ตัดสต๊อกแล้ว มีป้าย "รอซิงค์"; สถานะยังเป็น "แจ้งเลขติดตามแล้ว"; `ORD-24165` เป็น "จัดส่งสำเร็จ" แต่ยังมีป้าย "รอซิงค์"; ปิด fault แล้วป้ายหาย (ลองซิงค์ใหม่เอง) | FR-003, edge case ซิงค์ไม่สำเร็จขณะส่งถึง |
| 11 | นำเข้า Order สต๊อกพอ และ Order สต๊อกไม่พอ (ปุ่มนำเข้าที่ dashboard) | สต๊อกพอ → "ยังไม่ได้จับคู่" ; สต๊อกไม่พอ → "รอ Admin ตัดสินใจสั่งซื้อ" | US4, FR-007 |
| 12 | ไล่ดูทุกหน้า (dashboard, orders, shipping, cancel) | ไม่มีสถานะนอก 22 ค่า | FR-008, SC-003 |
| 13 | หลังสถานการณ์ทั้งหมดและเปิดหน้า `/shipping` อย่างน้อยหนึ่งครั้ง ตรวจทุก Order ที่เป็น "จัดส่งสำเร็จ" (รวม `ORD-23012` และ `ORD-24168`) | ทุกรายการมีสถานะขนส่ง "ส่งถึงลูกค้าแล้ว" ไม่มีรายการใดถูกเขียนทับเป็น "อยู่ระหว่างทาง" | SC-001, FR-015 |

เวลาเป้าหมาย: สถานการณ์ 1 ถึง 9 ไม่เกิน 10 นาที (SC-004)
