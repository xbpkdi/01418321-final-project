# Data Model: จัดลำดับสถานะ Order ให้ตรงตามที่ทีมอนุมัติ

ไม่เพิ่มฟิลด์ใหม่ใน `AppState` หรือ `Order` ทุกฟิลด์ด้านล่างมีอยู่แล้วใน `src/types/order.ts` และ `src/lib/workflow.ts`
สิ่งที่เปลี่ยนคือกฎว่าใครเขียนฟิลด์ไหนเมื่อไร รวมถึง `AppState.version` เปลี่ยนจาก 1 เป็น 2 (ดู research.md ข้อ 5)

## Order (ฟิลด์ที่เกี่ยวข้อง)

| ฟิลด์ | ความหมาย | ใครเขียน (หลังแก้) |
|---|---|---|
| `order_status` | หนึ่งใน 22 ค่า | 5S ตั้ง "แจ้งเลขติดตามแล้ว"; **เฉพาะกฎเลื่อนสถานะ** (ผลจาก 8A) ตั้ง "จัดส่งสำเร็จ"; 7S **ไม่เขียน** |
| `delivery_status` | `in_transit`, `delivered`, `failed`, `returned` จากขนส่ง | 8A (`dispatch` ตั้ง `in_transit`; `pollCarrier` อัปเดตตามที่ขนส่งตอบ) |
| `stock_deducted` | ตัดสต๊อกแล้วหรือยัง | 7S ตั้ง true; ตีกลับ (`pollCarrier`) และยกเลิกตั้ง false เมื่อคืนสต๊อก |
| `mp_stock_synced` | ซิงค์ยอดไป Rakuten แล้วหรือยัง | 7S (false เมื่อซิงค์ไม่สำเร็จ; ลองใหม่เองจนเป็น true) |
| `tracking_notified` | แจ้งเลขติดตามแล้วหรือยัง | 5S |

## การเปลี่ยนสถานะที่เกี่ยวข้อง

```text
อยู่ระหว่างจัดส่ง ──5S ส่งเลขติดตาม──▶ แจ้งเลขติดตามแล้ว
                                          │  7S: ตัดสต๊อก (ตั้ง stock_deducted, ไม่เปลี่ยนสถานะ)
                                          │  ยอดไม่พอ ──▶ รอดำเนินการด้วยตนเอง
                                          ▼
              stock_deducted = true  และ  delivery_status = delivered
                                          │  (กฎเลื่อนสถานะใน runAutomation)
                                          ▼
                                    จัดส่งสำเร็จ  (สถานะสิ้นสุด, 10A ลบได้)

จากอยู่ระหว่างจัดส่ง / รอแจ้งเลขติดตาม / แจ้งเลขติดตามแล้ว / จัดส่งสำเร็จ:
  ขนส่งตอบ failed   ──▶ จัดส่งไม่สำเร็จ
  ขนส่งตอบ returned ──▶ ตีกลับ/คืนสินค้า (คืนสต๊อกถ้า stock_deducted)
แจ้งเลขติดตามแล้ว + ยกเลิก (7A) ──▶ รอดำเนินการพิเศษ
```

## กฎความสอดคล้อง (invariants)

1. `order_status = "จัดส่งสำเร็จ"` เกิดได้เมื่อ `delivery_status = "delivered"` เท่านั้น (ใช้ตรวจ SC-001)
2. Order ที่ตัดสต๊อกแล้วตัดซ้ำไม่ได้ (`stock_deducted` เป็นตัวกัน)
3. ขนส่งยืนยัน `delivered` ก่อน 5S/7S เสร็จ: เก็บ `delivery_status` ไว้ สถานะไม่เปลี่ยนจน `stock_deducted` เป็นจริงและสถานะเป็น "แจ้งเลขติดตามแล้ว"
4. `delivery_status = "delivered"` ย้อนกลับเป็น `in_transit` ไม่ได้ (เปลี่ยนได้เฉพาะเป็น `returned` หรือ `failed` ตามที่ขนส่งแจ้ง) (FR-015)
5. `setStatus` ยังล้าง `manual_reason` และ `auto_error` ทุกครั้งที่เปลี่ยนสถานะ (พฤติกรรมเดิม)
